# AGENTS.md — the binding contract

In effect whenever code in this repo is touched, by agent or human.
When this conflicts with intuition, this wins.

## Commands

```sh
verify/build.sh      # build
verify/test.sh       # tests
verify/lint.sh       # lint / format check
verify/verify.sh     # full health gate — must pass before any push
```

Requires Xcode 26.2 with an iOS 18.6 or newer simulator runtime.

## Invariants — never regress these

1. **The iOS app is the product.** `ios/` holds a native SwiftUI app.
   The Next.js app in `src/` is a separate web surface and never becomes
   a dependency of the iOS app at runtime.
2. **No backend, no client secret.** Sign-in uses the GitHub OAuth
   device flow, which needs only a client ID. Never add a flow that
   requires a client secret in the app binary.
3. **The token lives in the Keychain**, never in `UserDefaults`, never
   in a log line, never in a URL query string.
4. **`ios/project.yml` is the project source of truth.** `.xcodeproj` is
   generated by `xcodegen` and is gitignored. Never hand-edit a pbxproj.
5. **Install happens through `itms-services://` only.** iOS gives an app
   no other way to install another app. Any code that pretends otherwise
   is a bug.
6. **Networking goes through `GitHubAPI`.** No `URLSession` calls in
   views. Views take injected protocols so tests can run without a
   network.
7. **The simulator is a first-class target.** Every screen must render
   and every non-install path must work on a booted simulator with no
   physical device attached.

## Landmine map

| Area | Why it bites |
|---|---|
| `ios/Apropos/Install/InstallService.swift` | `itms-services` needs an **https** manifest URL that iOS fetches unauthenticated. A private-repo asset URL always fails there. |
| `ios/Apropos/Core/DeviceFlowAuth.swift` | GitHub returns HTTP 200 with an `error` body during polling. Status code alone is not the signal. |
| `ios/Apropos/Core/ReleaseScanner.swift` | `.ipa` installs on device only; `.app.zip` runs on simulator only. Mixing them up produces an install that silently never appears. |
| `ios/project.yml` | Adding a source file needs no edit here (folders are globbed), but adding a *folder* outside `Apropos/` does. |
| `verify/simulator-smoke.sh` | `simctl` returns success for a launch that crashes 200 ms later. The script must re-check the pid. |

## House style

- Match the surrounding code's idiom, naming, and comment density.
- No demo scaffolding, no leftover diagnostics, no dead flags.
- Comments state constraints the code can't show — never narration.
- User-facing copy states the thing plainly; no reassurance microcopy.

## Process rules

- Branch from `main`; never commit to it directly.
- `verify/verify.sh` green before every push. Flaky gate → fix or
  quarantine in the same PR; never route around it.
- After adding/removing/renaming source files, run the stack's
  regeneration step (project gen, lockfile, tidy) and commit the result.
- Commit at boundaries; message says what changed and cites evidence.
- Docs move with behavior — same commit or PR.
- Report outcomes faithfully; failing is failing, with output.
